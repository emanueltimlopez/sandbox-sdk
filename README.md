# sandbox-sdk

A small SDK for creating and running Docker-backed sandboxes from Node.js/TypeScript.

> **Note:** This SDK is experimental. APIs, behavior, and generated Docker assets may change without notice.

The SDK generates a base `Dockerfile` for Bun projects, builds a Docker image from a local directory, and exposes helpers to create, start, stop, restart, remove, and read logs from containers.

## Requirements

- Node.js `>=22`
- Docker installed and running
- A Bun-compatible project when using the `Dockerfile` generated by `initProject`

## Local setup

```bash
npm install
npm run build
```

## Using the SDK

### Create a sandboxable project

`initProject(projectPath)` writes a `Dockerfile` into the provided directory.

```ts
import { SSDK } from "./index.ts";

const sdk = new SSDK();

await sdk.initProject("./my-bun-app");
```

The generated `Dockerfile` uses this template:

```dockerfile
FROM oven/bun:latest
WORKDIR /app
COPY . .
RUN bun install
CMD ["bun", "run", "index.ts"]
```

### Build an image

```ts
await sdk.buildImage("./my-bun-app", "my-bun-app:latest");
```

During the build, the SDK creates the Docker context from `projectPath` and ignores `.git` and `node_modules`.

### Create and run a container

```ts
const container = await sdk.createAndRunContainer(
  "my-bun-app:latest",
  "my-bun-app-instance-1",
);
```

### Stream stdout logs

```ts
const logs = await sdk.getContainerLogs(container);
logs.pipe(process.stdout);

await container.wait();
```

### Manage the lifecycle

```ts
await sdk.stopContainer(container);
await sdk.restartContainer(container);
await sdk.removeContainer(container);
```

### Complete example

```ts
import { SSDK } from "./index.ts";

const sdk = new SSDK();
const projectPath = "./my-bun-app";
const imageTag = "my-bun-app:latest";
const containerName = "my-bun-app-instance-1";

await sdk.initProject(projectPath);
await sdk.buildImage(projectPath, imageTag);

const container = await sdk.createAndRunContainer(imageTag, containerName);

const logs = await sdk.getContainerLogs(container);
logs.pipe(process.stdout);
await container.wait();

await sdk.removeContainer(container);
```

## Examples

- `examples/just-code`: builds and runs a simple Bun project in one sandbox.
- `examples/hermes-agent`: runs Hermes Agent in one sandbox using the official Docker image.
- `examples/multiple-agents`: runs the same prompt in separate Codex and Claude Code sandboxes.

## Public API

### `new SSDK()`

Creates an SDK instance. Internally, it initializes a `dockerode` client using the Docker configuration available in the environment.

### `initProject(projectPath: string)`

Creates a `Dockerfile` in `projectPath`.

Returns:

```ts
Promise<{ success: boolean; path: string }>
```

### `buildImage(projectPath: string, tag: string)`

Builds a Docker image using `projectPath` as the context and `tag` as the image tag.

Returns:

```ts
Promise<{ success: boolean; tag: string }>
```

### `createAndRunContainer(image: string, name: string, options?)`

Creates and starts a container using the provided image and name.

Options:

```ts
{
  env?: Record<string, string | undefined>;
  cmd?: string[];
  binds?: string[];
  ports?: Record<string, string>;
}
```

Returns:

```ts
Promise<Docker.Container>
```

### `stopContainer(container: Docker.Container)`

Stops a container.

### `removeContainer(container: Docker.Container)`

Removes a container.

### `restartContainer(container: Docker.Container)`

Restarts a container.

### `getContainerLogs(container: Docker.Container)`

Streams the container's `stdout` logs and keeps following until the container closes.

Returns:

```ts
Promise<NodeJS.ReadableStream>
```

## Developing the SDK

### Repository structure

```text
.
├── index.ts          # SDK source code
├── examples/         # Local usage examples
├── dist/             # Compiled artifacts
├── package.json      # Metadata, scripts, and dependencies
└── tsconfig.json     # TypeScript configuration
```

### Install dependencies

```bash
npm install
```

### Build

```bash
npm run build
```

The build compiles `index.ts` into `dist/` and generates:

- `dist/index.js`
- `dist/index.d.ts`
- source maps
- declaration maps

### Run a local example

Examples are local usage references. They are not part of the TypeScript build because `tsconfig.json` only includes `index.ts`.

If you want to use one as a smoke test, first build the SDK, verify that the example imports from the local source or build output, then run it with a TypeScript + ESM-compatible runner.

Make sure Docker is running before executing any test that builds images or creates containers.

## Development notes

- The SDK is configured as ESM (`"type": "module"`).
- TypeScript uses `NodeNext` for both `module` and `moduleResolution`.
- `dockerode` is a runtime dependency.
- `@types/dockerode`, `@types/node`, and `typescript` are development dependencies.
- The build context excludes `.git` and `node_modules`, but it does not parse `.dockerignore` yet.
